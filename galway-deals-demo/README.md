# Passing By: Galway prototype

Walk through Galway city centre and get notified about deals and events as you pass shops.

- **GPS zone (~60 m):** a heads-up that something good is nearby.
- **Bluetooth beacon (~7 m):** "you're at the door", with the deal.
- **One alert per shop:** the "nearby" alert waits up to a minute of walking. If you reach the door first, you only get the door alert.
- **Your guide (learning agent):** learns from your *Interested* / *Not for me* taps, mutes what you don't like, and stars your top picks on the map.
- **Beacon security:** shows why a basic beacon can be faked, and how rotating, server-checked beacon IDs stop it.

> **Demo only.** The businesses are real Galway places, but every deal is made up. None of them is involved in or endorses this project.

## What is real and what is simulated

| Part | In this prototype | In a real product |
| --- | --- | --- |
| Your location | A walker you move on the map | Phone GPS, in the background |
| Bluetooth beacons | Signal strength simulated from distance, with random noise | Real BLE beacons at each shop door |
| Beacon IDs | Generated by the Flask server | Generated by the beacon hardware |
| Beacon checks | Real: Flask verifies each ID | Same |

Browsers can't scan for Bluetooth beacons or track location in the background. A real version needs a native phone app.

## How the beacon security works

A basic beacon broadcasts the same ID forever. Anyone nearby can record it and copy it onto a cheap beacon somewhere else. An app that trusts the ID will show the shop's deal in the wrong place, or show a completely made-up "deal" with a scam link.

This prototype uses three checks instead:

1. **Rotating IDs.** Each beacon broadcasts `HMAC(shop_key, time_window)`, cut to 8 bytes. The ID changes every 30 seconds. Only the server knows the shop keys.
2. **Freshness.** The server accepts IDs from the current or previous window only. A recorded ID stops working within a minute.
3. **Location.** The app sends a rough location (rounded to about 100 m). If the beacon belongs to a shop more than 150 m away, it was cloned or relayed, so it's rejected.

GPS zones are worked out on the device. Your location is only sent (rounded) when a beacon needs checking, and the server doesn't store it.

Try it in the app: use **Try an attack**, then switch between **Checked beacons** and **Basic beacons**.

## How the guide learns

The guide is a small on-device learning agent (an epsilon-greedy bandit), not a chatbot.

- Each category (coffee, food, books, clothes & shopping, markets) keeps a Beta(likes, dislikes) score, starting slightly positive.
- **Interested** adds a like, **Not for me** adds a dislike. Each shop also gets a small bonus or penalty of its own.
- An alert is shown if its expected liking is at least 0.45. Otherwise it's skipped, except 10% of the time, so the guide can notice if your taste changes. Those alerts are labelled.
- In practice: one "Not for me" mostly mutes that shop, two mute the category, and one "Interested" brings it back.
- Top picks are the highest-scoring shops in the categories you chose. They get a star on the map.
- Every skip is explained in plain English ("Skipped Dela. You liked 0 of 2 food and drink alerts.").
- What you like is stored only in your browser (localStorage). It is never sent to the server.

The logic is in `src/agent.js`.

## Project layout

```
api/
  index.py       Flask app (routes)
  _beacons.py    Rotating IDs, checks, attack handling
  _data.py       Shops, demo deals, walking route

  App.jsx        Simulation loop, GPS zones, Bluetooth, notifications
```

## Run it locally

You need Node 20+ and Python 3.10+.

```bash
# 1. Backend (terminal 1)
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python api/index.py                # runs on http://127.0.0.1:5000

# 2. Frontend (terminal 2)
npm install
npm run dev                        # open the URL it prints
```

The dev server forwards `/api` calls to Flask, so both must be running.

## API

| Method | Path | What it does |
| --- | --- | --- |
| GET | `/api/health` | Health check |
| GET | `/api/shops` | Shops, demo deals, walking route |
| GET | `/api/sim/broadcasts` | What each simulated beacon is broadcasting right now |
| POST | `/api/beacons/resolve` | Checks a beacon the phone heard |

Example:

```bash
curl -X POST http://127.0.0.1:5000/api/beacons/resolve \
  -H "Content-Type: application/json" \
  -d '{"mode":"secure","beacon":{"eid":"f00dfacecafe1234"},"position":{"lat":53.272,"lng":-9.052}}'
```

## Deploy to Vercel

Use Vercel, not Netlify. Netlify can host the React part but can't run the Flask backend.

1. Push this repo to GitHub.
2. In Vercel, choose **Add New → Project** and import the repo. It detects Vite automatically.
3. Under **Environment Variables**, add `BEACON_MASTER_SECRET`. Generate a value with:
   `python -c "import secrets; print(secrets.token_hex(32))"`
4. Deploy. The React app is served as static files and `/api/*` runs as a Python function.
5. Open the live link on your phone and on a laptop before sharing it.
